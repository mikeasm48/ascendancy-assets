# 06 — Метаданные конструкторов кораблей

Рядом с каждым `*_shipyard_constructor.glb` в бандле может лежать
**необязательный** файл метаданных: то же имя, расширение `.json`.

```
races/worms/ships/worms_shipyard_constructor.glb
races/worms/ships/worms_shipyard_constructor.json   <- метаданные
races/bionics/ships/shipyard_constructor.glb
races/bionics/ships/shipyard_constructor.json
```

Файл описывает две вещи, которых нет и не может быть в самом glTF, и
которые до этого приходилось руками править в локальном
`~/.ascendancy/model-cache.json` каждой отдельной установки игры — без
какой-либо возможности раздать результат игрокам.

## Формат

```json
{
  "invertX": false,
  "invertY": false,
  "invertZ": true,
  "parts": {
    "Worms_Small": "HULL",
    "Worms_Small_Segmented": "ENGINE",
    "Body_Segment_Eye_Orb": "COCKPIT",
    "Worms_Body_Segment_stix": "WEAPON",
    "Worms_Body_Segment_Jaws": "WING"
  }
}
```

Все поля необязательны: отсутствующий флаг = `false`, отсутствующий
`parts` = пустой. Незнакомые ключи игнорируются — формат можно
расширять. Битый или отсутствующий файл не фатален: модель просто
разбирается автоклассификатором, как и до появления метаданных.

### `invertX` / `invertY` / `invertZ` — разворот всей модели

Зеркалит **весь кит** относительно его собственного начала координат в
момент инстанцирования модели. Нужен, когда кит собран «лицом» не в ту
сторону: игра считает носом корабля направление `-Z`, а элементы
worms-кита смотрят в `+Z`.

Без этого флага каждую деталь пришлось бы зеркалить вручную в редакторе
кораблей, и штатное место двигателя (корма) всегда оказывалось бы на
носу.

Разворот применяется одинаково во всех четырёх потребителях модели —
анализ узлов, картинки деталей в каталоге, превью конструктора и запечка
собранного корабля для боя, — поэтому редактор показывает ровно то, что
потом летает.

### `parts` — назначение узлов

`имя узла` → роль. Роль — константа `PartType` игры:

| PartType | Слот в конструкторе |
| --- | --- |
| `HULL` | Hull |
| `COCKPIT` | Bridge |
| `ENGINE` | Engine |
| `WEAPON` | Weapon |
| `SHIELD` | Shield |
| `SENSOR` | Scanner |
| `WING`, `CARGO`, `DECORATIVE` | Aux |

Автоклассификатор игры (`ModelAnalyzer`) угадывает роль по имени узла,
его объёму, пропорциям и положению вдоль корпуса. На технических китах
(humans) он попадает точно, на органике — почти нет: worms-кит целиком
разбирался как `HULL`. Здесь записывается замысел художника.

Перечислять нужно **только те узлы, где автоклассификация неверна**.
Неназванный узел сохраняет угаданную роль. У humans-кита расхождений нет
вообще, поэтому файла метаданных у него нет.

## Приоритет: ассеты выше локального кэша

`~/.ascendancy/model-cache.json` — это **кэш анализа геометрии** данной
установки, а не источник правды. Роли из `parts` накладываются поверх
того, что лежит в кэше, поэтому устаревший или руками поправленный кэш
не может перебить то, что заявлено в ассетах.

Сам кэш при этом продолжает хранить чистый результат автоанализа —
метаданные в него не записываются. Разворот по осям меняет геометрию,
которую видит анализатор, поэтому при первом запуске после добавления
`invert*` структурный хэш модели не совпадёт и кит будет переанализирован
один раз; дальше снова попадание в кэш.

## Как получить содержимое `parts` для нового кита

1. Сохранить текущий кэш: `cp ~/.ascendancy/model-cache.json
   ~/.ascendancy/model-cache_base.json`.
2. Удалить `model-cache.json` и запустить редактор кораблей для нужной
   расы, чтобы игра пересобрала кэш чистым автоанализом:
   ```bash
   ./gradlew run -Dascendancy.debug.screen=ship-constructor \
       -Dascendancy.debug.race=ORFA \
       -Dascendancy.debug.capture=true -Dascendancy.debug.capture.at=3
   ```
3. Сравнить `model-cache_base.json` с новым `model-cache.json` по полю
   `partType`; всё, что расходится, — это и есть ручная правка, её и
   переносим в `parts`.
